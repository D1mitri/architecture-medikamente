# Список проблемных зон:
1. Данные хранятся в файлах Excel или хранят в виде сканов, материалы лежат на общем диске.
2. Отсутствует единая система хранения и управления данными.
3. Работа с конфиденциальными данными и PII не в полной мере отвечает требованиям российского законодательства.
4. Высокие риски утечки данных.
5. Двойной учёт в Excel и 1C платежей.
6. IT-продукты построены на разных архитектурных принципах (монолит, общие ресурсы).
7. IT-продукты развёрнуты на собственном сервере компании.
8. Любой бизнес-процесс в компании сопровождается обращением к конфиденциальным данным разного уровня.
9. Конфиденциальную информацию сотрудники обрабатывают вручную.
10. Отсутствует аудит действий при работе с данными и в IT-системах.
11. Внутренние потоки данных между IT-продуктами никак не контролируются.
12. Кроме доменной аутентификации, со стороны систем обработки нет ограничений на доступ к данным.

# Список данных для защиты:
Медицинские карты
Персональные данные (Ф. И. О., дата рождения, телефон и электронная почта). 
Дополнительные данные из расширенной формы: адрес прописки, место работы или учёбы, хронические заболевания.

# Список инструментов, способов и мер, которые позволят обеспечить конфиденциальность данных:
Обязательно выполнить классификацию данных (ориентироваться на ФЗ-152).
Зафиксировать правила обработки персональных данных.
Настроить журналирование действий при работе с персональными и конфиденциальными данными.
Проводить тренинги по безопасности для сотрудников.
Данные на устройстве необходимо шифровать, например с помощью FileVault.
При передаче по сети данные необходимо шифровать, использовать TLS 1.3, HTTPS.
Для доступа к данным настроить доступ по ролям RBAC и по атрибутам ABAC.
Руководствоваться принципом минимальных привилегий.
Собирать только необходимые данные.
Удалять данные, если они больше не нужны.
При работе с данными использовать обезличивание.

# Тегирование данных:
Для персональных данных добавить тегирование PII (персональная информация).
С помощью тегов можно установить, кто имеет право видеть, изменять или передавать данные.
Выполнить интеграцию тегирования и модели RBAC, чтобы автоматически проверять, соответствует ли роль пользователя уровню доступа, заданному тегами данных.

# План действий по тегированию данных:
1. Для предотвращения утечки данных использовать Symantec DLP.
2. Внедрить Informatica Data Catalog для автоматической маркировки на основе правил профилирования и классификации данных.
3. Использовать Keycloak для управления идентификацией и доступом. 
4. Настроить мониторинг и аудит тегированных данных с помощью Collibra Data Intelligence Cloud
5. Проинформировать сотрудников о маркировке данных и защите конфиденциальной информации.
6. Поддержка и обновление тегов.
